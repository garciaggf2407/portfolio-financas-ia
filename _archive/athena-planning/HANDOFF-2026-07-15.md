## Lições reutilizáveis (technical debt pattern, não deste projeto especificamente)

- Filtro opcional em JPQL (`(:param IS NULL OR expr = :param)`) contra
  Postgres: se `expr` não for uma coluna simples (função, cast, etc.),
  adicionar `CAST(:param AS <tipo>)` sempre — Postgres/Hibernate podem
  falhar em inferir o tipo especificamente no caso NULL, e um teste que
  só passa valores não-nulos nunca pega isso.
- Testcontainers com container singleton compartilhado entre classes de
  teste: todo `@RabbitListener`/consumer real de cada contexto Spring
  fica vivo e compete por filas de nome fixo. Isolar por nome único via
  property quando uma classe específica faz asserções sensíveis a
  timing (não vale renomear tasks/IDs já commitados só por
  consistência cosmética — rastreabilidade com git > pureza de padrão).
